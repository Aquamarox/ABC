## 1. Условие задачи

Первая задача о магазине. В магазине работают три отдела,
каждый отдел обслуживает один продавец. Покупатель, зайдя в
магазин, делает покупки в одном или нескольких произвольных
отделах, обходя их в произвольном (случайном) порядке. Если
в выбранном отделе продавец не свободен, покупатель становится
в очередь и ожидает, пока продавец не освободится.
Создать многопоточное приложение, моделирующее рабочий день магазина.
Каждого покупателя и продавцов моделировать отдельными потоками.
Размер очереди не оговаривается. Считается, что для данной задачи она не ограничена (но моделирование должно быть в разумных
пределах).


Необходимо создать **многопоточное приложение** на C/C++ с использованием POSIX Threads, моделирующее рабочий день магазина. Каждый покупатель и каждый продавец моделируются отдельным потоком.  

---

## 2. Сценарий предметной области

1. В магазине работают три отдела. Каждый отдел обслуживается одним продавцом, который обслуживает одного покупателя за раз.  
2. Покупатель приходит в магазин и случайным образом выбирает количество отделов для посещения (от 1 до 3).  
3. Порядок посещения отделов также выбирается случайным образом.  
4. Если продавец свободен, покупатель сразу обслуживается. Если нет — становится в очередь.  
5. После обслуживания покупатель либо идёт в следующий отдел, либо покидает магазин.  
6. Продавец обслуживает покупателей по мере их поступления.  

> Каждый покупатель и каждый продавец отображается отдельным **потоком** в программе.

## 3. Модель параллельных вычислений

### 3.1. Программа на 8 баллов (`shop.cpp`)

- Синхронизация потоков осуществляется с помощью **мьютексов** и **семафоров POSIX**.  
- Каждый продавец — отдельный поток, который ждёт семафор для своего отдела.  
- Каждый покупатель — отдельный поток, который вызывает `sem_post` для выбранного отдела и ждёт обслуживания.  

### 3.2. Программа на 9–10 баллов (`shop_cond.cpp`)

- Используются **условные переменные (`pthread_cond_t`)** и мьютексы.  
- Очередь реализована через счётчик `d.queue` для каждого отдела.  
- Продавец ждёт условную переменную, если очередь пуста.  
- Покупатель увеличивает счётчик очереди и сигналит продавцу.  
- Это позволяет явно моделировать очередь и демонстрирует другой синхропримитив.

## 4. Входные данные программы

- Число покупателей: **1–50**, задаётся параметром командной строки `-n <buyers>` или через конфигурационный файл `-c <file>`.

```

config2.txt: buyers=10

```

## 5. Генерация случайных данных

- Количество посещаемых отделов: 1–3 (случайное число).  
- Порядок посещения отделов: случайная перестановка [0,1,2].  
- Время обслуживания покупателя: 1–3 секунды (случайное число).  

> Случайные числа генерируются с помощью `rand()` и `srand(time(nullptr))`.
